# Final Model Evaluation & Packaging — EcoPackAI

**Evaluation notebook:** `ml/notebooks/06_final_evaluation.ipynb` → `ml/metrics/final_model_comparison.csv`
**Package:** `src/inference/predictor.py` (prediction interface), `src/inference/metadata.json`
(generated by `src/inference/build_metadata.py`) · **Tests:** `tests/test_predictor.py`

## 1. Evaluation Setup

Every variant uses the same data and splits as all earlier experiments:
403 materials, 80/20 split with `random_state=42` (322 train / 81 test), the same
5 cross-validation folds on the training set, and the same 31-feature preprocessing
pipeline. Each model is scored on three sets: **train** (data it learned from),
**CV** (5-fold cross-validation), **test** (held-out, never used for any decision).

Variants per target: the naive material-type average, the v1 baseline, the production
model, and the other production algorithm as an alternative (trained in the notebook
for comparison only; not saved).

## 3. Model Selection

**Cost → Random Forest (production v1).** Best of all variants on every test metric
(MAE 43% lower than the baseline). Linear Regression has a lower CV RMSE because Random
Forest makes a few large errors on boundary materials (documented in
`rf_cost_training_summary.md`); its typical error (CV MAE 0.247 vs 0.357) is far lower.

**CO2 → XGBoost (production v1), kept by decision.** It improves on the Decision Tree
baseline (test RMSE −31%), but two references score better:
- The **untuned Random Forest** is slightly better on all metrics (test MAE 0.0350 vs
  0.0358; CV RMSE 0.069 vs 0.083).
- The **material-type average** is better still, because CO2 in this dataset is set by
  material type (see `xgb_co2_training_summary.md`).

XGBoost was kept because it is the model specified in the project architecture and the
difference is negligible for recommendations: 0.0008 kg CO2/kg in test MAE, against gaps
of 0.2–2.7 kg/kg between material types. A Random Forest CO2 model is planned as v2
(`docs/model_version_history.md`). Learned models are preferred over the lookup because
they respond to a material's properties, while a lookup cannot handle a new or atypical
material.

## 4. Generalisation

| Model | Train RMSE | CV RMSE | Test RMSE | Test / train |
|---|---|---|---|---|
| Random Forest (cost) | 0.192 | 0.480 | 0.310 | 1.6× |
| XGBoost (CO2) | 0.0390 | 0.0833 | 0.0537 | 1.4× |
| Decision Tree (CO2 baseline) | 0.0012 | 0.0823 | 0.0780 | 66× |

- Both production models score worse on unseen data than on training data, as expected,
  but by a moderate factor (1.4–1.6×). Test R² stays above 0.99 for both.
- The Decision Tree baseline memorises its training data (train RMSE 0.0012, 66× lower
  than test); the production models do not overfit like this.
- The test set is somewhat easier than the average CV fold for both models (test RMSE
  below CV RMSE), so CV figures are the more conservative estimate of live performance.

## 5. Packaging

### Contents

| Artifact | Purpose |
|---|---|
| `ml/models/rf_cost.joblib` | Fitted preprocessing pipeline + Random Forest (one object) |
| `ml/models/xgb_co2.joblib` | Fitted preprocessing pipeline + XGBoost (one object) |
| `src/inference/metadata.json` | Model names, versions, training dates, hyperparameters, metrics, targets, feature schema, data version, library versions, file fingerprints |
| `src/inference/build_metadata.py` | Generates `metadata.json` from the artifacts and experiment records |
| `src/inference/predictor.py` | `MaterialPredictor`: the single prediction interface |

Preprocessing is inside each `.joblib` pipeline, so raw material attributes go in and
predictions come out; nothing can be applied in the wrong order.

### metadata.json

Generated, not hand-written, so it always matches the artifacts:
- **Models:** name, version, experiment ID, training date, target, unit, hyperparameters,
  5-fold CV and test metrics, selection note, artifact path and SHA-256 fingerprint.
- **Feature schema:** the 18 raw input features with type (numeric / categorical /
  ordinal), training range for numeric columns, allowed values for categorical ones,
  and the 31 encoded model features.
- **Data:** dataset version v1, source file and its SHA-256, row count, split settings.
- **Library versions:** scikit-learn 1.5.1, xgboost 2.1.0, pandas 2.2.2.

### MaterialPredictor

```python
from inference.predictor import MaterialPredictor

predictor = MaterialPredictor()
predictor.predict({"material_type": "Cardboard", ...})   # one material  -> dict
predictor.predict(materials_df)                           # many materials -> DataFrame
predictor.info()                                          # model summary
```

On loading it:
1. warns if the installed scikit-learn or xgboost version differs from the saved one;
2. checks each model file's SHA-256 against `metadata.json` and refuses to load a file
   that changed (e.g. retrained without regenerating the metadata);
3. loads the fitted pipelines (no retraining).

On every prediction it validates the input against the schema:

| Input problem | Behaviour |
|---|---|
| Missing column | Error naming the columns |
| Non-numeric value in a numeric column | Error |
| Unknown recyclability category (ordinal) | Error listing allowed values |
| Unseen material/packaging type or region | Warning; the model treats it as "none of the known categories" |
| Numeric value outside the training range | Warning: tree models do not extrapolate |
| Missing values | Warning; filled with training medians/modes by the pipeline |
| Extra columns | Ignored |

### Recommendation pipeline integration

The ranking engine (`src/recommendation/ranker.py`) now gets its predictions through
`MaterialPredictor` instead of loading the models itself, so the whole project has one
prediction entry point. `outputs/material_rankings.csv` is byte-identical before and
after this change.

## 6. Validation Checklist

| Check | Evidence (`tests/test_predictor.py`, 17 tests) |
|---|---|
| Supports batch and single inputs | dict → dict, DataFrame / list of dicts → DataFrame; single and batch results agree |
| Preprocessing consistency maintained | Predictor output equals the original pipelines; test-set MAE equals the metadata value |
| Metadata accurately documents the models | Required fields present; feature list equals the pipeline's; metrics generated from experiment records |
| Models load correctly without retraining | Loading with warnings-as-errors (no version mismatch); a changed model file is detected |
| Ready for recommendation integration | Ranker uses the predictor; identical rankings |

Predictions are reproducible to about 1e-14: Random Forest averages its trees in
parallel threads, which can change the last floating-point digit between calls.
Tests treat differences below 1e-9 as identical; saved outputs are rounded.

## 7. Limitations

- Models are trained on 403 materials in 6 packaging groups; materials unlike these
  (new material families) are outside what the models have seen.
- Cost and CO2 are predicted per material, not per product.
- CO2 prediction cannot beat the material-type average with the available features;
  improving it needs new data (manufacturing process, energy source, transport).
